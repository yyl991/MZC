# 项目交接文档：粉丝向互动叙事网页模拟器（橙粉色捡起来）

## 📌 1. 项目概述
这是一个基于纯前端（HTML/CSS/Vanilla JS）的“iPhone 模拟器 + 互动叙事”网页游戏。玩家通过操作模拟的手机，接收消息、接听电话、探索 APP，来推进一段粉丝向/乙女向的剧情。
**技术栈**：原生 JavaScript、HTML5、CSS3。无框架（无 Vue/React），无后端。
**核心机制**：时间线（Timeline）驱动。随着游戏时间流逝（tick 函数），系统会自动推送微信消息、触发来电、触发剧情选择等。

---

## 📂 2. 文件结构与核心职责
本项目代码高度模块化，请严格按照职责修改对应文件，**不要跨文件乱塞逻辑**。

*   `index.html`：入口文件。定义了手机外壳（`#phone`）、各个图层（`#lockL`, `#homeL`, `#appL`, `#ov`）以及 BGM `<audio>`。负责按顺序加载所有 JS 文件并启动 `initApp()`。
*   `app.js`：**操作系统的核心**。包含全局变量、状态机、游戏时钟（`tick`）、锁屏/密码逻辑、APP 的打开/关闭动画、全局弹窗（`#ov`）、**电话系统（接听/挂断/拨号盘）**、以及时间线检查器 `storyTick`。
*   `chat.js`：**微信 App 的核心**。负责聊天列表、聊天详情、消息渲染（文字/图片/表情/语音/视频）、长按撤回、双击拍一拍、底部输入框和虚拟键盘。
*   `story.zh.js`：**剧情数据核心**。包含角色配置（`S.roles`）、聊天回复剧本（`S.chats`）、全局时间线（`S.timeline`）、通话剧本（`S.callScripts`）、备忘录/日历数据等。**所有文本内容都在这里改**。
*   `chat_history.js`：独立的微信历史聊天记录库（格式统一，方便批量添加回忆）。
*   `data_extra.js`：其他次要 APP 的 UI 占位视图（如微博、闲鱼、B站、相册等）。
*   `style.css`：全局样式。包含 iOS 原生组件的样式、微信 UI 样式、动画效果。
*   `utils.js`：工具函数（如日期格式化、翻译函数 `t()` 等）。

## ⚠️ 5. 开发避坑指南与修改规范

1.  **绝对不要用 Emoji 作为 JS 对象键名**：
    *   **错误**：`S.roles = { '🐷': { ... } }`
    *   **正确**：`S.roles = { 'pig': { ... } }`，然后用 `S.display = { pig: '🐷' }` 映射，渲染时用 `dn('pig')`。
2.  **内联事件绑定容易引发截断**：
    *   写 `onclick="openChat('${name}')"` 时，如果 `name` 包含引号或特殊字符，会导致 HTML 属性截断。请用 `&quot;` 转义，或者改用事件委托。
3.  **严格区分 `me` 和 `them`**：
    *   聊天数据格式必须遵守：`['文本内容', 'them'/'me', '时间']`。
    *   如果是系统提示，必须用 `'sys'` 作为后缀。
4.  **长文本与图片路径**：
    *   聊天记录里发图片格式必须是：`['[图片] ./data/chat/xxx.jpg', 'them', '时间']`。
    *   发语音格式必须是：`['[语音] 5|./data/audio.mp3|转写文字', 'them', '时间']`。
5.  **强刷缓存**：
    *   修改 JS/CSS 后，提示用户或自己按 `Ctrl + F5` 强制刷新，避免测试时怀疑人生。
6.  **函数挂载**：
    *   如果在 HTML 内联调用函数（如 `onclick="foo()"`），该函数必须暴露在全局作用域（`window.foo = foo`），否则会报错。
